## 2. 页面目标与信息结构

首页是三维地图。用户首先能够辨认“在哪里、看什么变量、代表什么时间”，随后点选位置和记录体感。保留研究探索所需的来源与方法入口，首页不铺陈模型系数或研究结论。

建议只有一个持续存在的地图工作区；地点详情、打卡、我的记录、数据说明以面板或对话框打开，避免每次操作销毁三维场景。

| 界面区域 | 默认内容 | 展开内容 |
| --- | --- | --- |
| 顶栏 | 平台名称、场景/地点搜索、当前模式、我的记录 | 场景选择、登录 |
| 左侧控制栏 | 环境变量、基础图层、体感筛选 | 透明度、来源与覆盖说明 |
| 中央地图 | 地形、白色建筑、绿色树冠、当前环境图层、近期打卡 | 选中点、覆盖边界、对象高亮 |
| 右侧详情栏 | 未选点时为当前视图状态与操作提示 | 地点环境、对象属性、体感详情、打卡表单之一 |
| 地图工具 | 复位、俯视/倾斜、指北、定位、导出 | 操作帮助 |
| 底部时间轴 | 现在、时间选择、播放、有效时间范围 | 逐小时刻度、区间平均说明 |
| 图例与页脚 | 当前变量单位、缺测样式、必要来源署名 | 数据方法、完整元数据 |

```text
│ 环境变量     │ 场景名 / 数据状态                       │ 地点详情    │
│ 气温 湿度 风 │                                          │ 气温与时间  │
│ 露点 辐射    │      白色建筑 + 绿色树冠 + 地表环境       │ 来源与尺度  │
│              │                                     工具 │ 逐时变化    │
│ 要素图层     │                                          │ 附近体感    │
│ 近期体感筛选 │ 图例                    [记录此处体感]   │             │
│              │ [现在] [播放] ──── 时间轴 ──── 实际时刻   │             │
├──────────────┴──────────────────────────────────────────┴─────────────┤

└───────────────────────────────────────────────────────────────────────┘
```

这是布局示意，不是已经实现的页面截图。

- 桌面宽度 ≥1280 px：顶栏约 64 px，左栏 248 px，右栏 320 px；中心地图随窗口伸缩。侧栏可收起，收起后保留恢复入口。
- 中央地图是视觉主体。沿用低饱和灰绿地形、近白建筑、绿色树冠、蓝灰水体、柔和光影；环境色带开启时降低基础地表颜色干扰。
- 基础色参考原项目：背景 `#f4f6f3`、面板 `#ffffff`、正文 `#263b36`、次级文字 `#64786f`、主操作 `#176c53`、边框 `#e0e7e1`。这些是初始 token，成品需检查所有实际搭配的对比度。
- 正文与控件 14–16 px，辅助文字不低于 12 px，面板标题 18–20 px，关键读数 28–36 px；不沿用原页面大量 8–10 px 信息字号。
- 字体使用系统中文无衬线，不依赖在线字体；数字采用等宽数字特性。间距按 4/8/12/16/24 px，圆角以 8–12 px 为主，阴影轻量。
- 地图操作图标采用统一 SVG，均有名称和可见焦点。深绿用于操作选中态，不同时承担所有变量的科学色带。
- 普通文字对比度目标至少 4.5:1，关键边界与焦点至少 3:1；状态同时提供文本/图标，不只靠红绿区分。

## 4. 三维场景与引擎边界

### 4.1 首版引擎建议

建议 CesiumJS 承载上海地理场景，复用 sunlight-viewer 的多源场景组织与白膜表现；Vue 3 + TypeScript + Vite 管理交互外壳，Pinia 管理少量跨组件状态。现有原生 JavaScript 逻辑通过适配器逐步迁入，不要求重写全部渲染逻辑。

Three.js 局部样区作为后续可选视图，首版不同时维护两个可见三维引擎，也不并行引入 OpenLayers。Cesium 无法运行时使用可访问的地点列表和手动坐标输入承接查询/打卡；这不是声称已具备另一套二维地图。

### 4.2 视觉与数值分离

- 视觉太阳与阴影跟随选定场景时刻；科学图层读取后端固定版本成果。关闭树冠显示不改变局地辐射数值。
- “显示建筑/树冠”是显示操作；原 viewer 的“树冠参与遮挡”情景切换不直接迁入实时首页。未来若有已发布对照情景，作为有明确版本的模型情景选择。
- 环境默认绘制在产品定义的接收面上，不将水平地面值涂到立面或树叶后称为其表面温度。
- 树冠遮挡地面色带时提供树冠半透明或临时隐藏；高亮对象不改变其科学属性。
- 仅净短波可用时展示区域净短波背景及独立阴影；局地下行短波不可用项显示原因，不通过视觉阴影生成 W/m²。
- 接收高度、空间尺度和时间平均语义由产品元数据驱动，不复用历史 viewer 的固定数值。

### 4.3 相机与选点

默认使用可辨认道路与建筑的倾斜视角，复位到场景清单定义的位置。保留俯视、指北、缩放与定位；手势采用 Cesium 默认行为并提供简短帮助，不照搬 Three.js 的旋转/平移键位说明。

单击候选包括 UGC、建筑/树冠/POI 和地面。重叠时提供小型对象选择列表；常驻“查询此处环境”动作可切换到地面查询。建筑屋顶拾取得到的三维高度不能直接解释为行人接收高度。无可靠地面交点时要求用户俯视重选，不静默落到任意椭球位置。

拖动超过阈值视为移动地图，不触发点击。进入打卡选点模式后，地图点击仅移动草稿标记，不同时打开对象详情；确认位置后退出该模式。

## 5. 图层与色彩表达

| 图层组 | 控件与默认行为 | 科学表达约束 |
| --- | --- | --- |
| 环境主图层 | 气温默认；湿度、风速、露点、区域净短波、局地下行短波按能力切换 | 同时只显示一个主要连续色带；名称、单位与图例同步 |
| 风方向 | 可叠加稀疏箭头，动画可选 | 风向按 API 约定；动效不是三维街谷流场 |
| 场景要素 | 建筑、树冠、地形、水体、绿地、道路、POI 独立显隐 | 隐藏不改变已计算结果；地形缺失明确提示 |
| 太阳阴影 | 独立开关 | 标明几何模拟；环境判读模式可降低装饰阴影，避免改变色带读感 |
| UGC | 近期记录默认开启，按缩放聚合 | 时间按体验时间；图标、描边与形状区别于背景色带 |
| 数据覆盖 | 边界、缺测纹理和状态提示 | 未加载、无数据、范围外与零值分别表达 |

气温使用可读的顺序色带；需要表达偏差时才使用有明确中点的发散色带。湿度、风速与辐射各自使用单位一致的顺序色带，不以红色默认表示健康危险。UGC 类别提供文字标签和可辨认符号，不能只用背景热色。

时间播放期间图例范围保持固定；如果允许用户切换自动范围，须明显标明“当前范围”，导出记录范围。超出色带端点的有效数值显示上下溢出标记，点查询仍返回真实值。

图层卡片具有未加载、加载中、可用、部分缺失、失败状态；勾选与加载成功是两件事。某层失败不阻止其他层或打卡表单。图层过多时按组折叠，不把每个技术字段放入主控栏。

## 6. 时间轴与实时更新

### 6.1 三种独立时间

| 状态 | 含义 | UI 处理 |
| --- | --- | --- |
| 场景时间 | 太阳几何位置对应时刻 | 时间轴选定时间，注明光影模拟 |
| 环境时间 | 各变量 resolved_time 或平均区间 | 读数旁显示真实有效时间，必要时显示与场景时间偏差 |
| UGC 时间筛选 | 用户体验发生的区间 | 单独的“近期/日期范围”筛选，不由预报播放自动改写 |

时间轴依据 catalog 的有效范围生成，不硬编码任意年份或保证永远有完整 48 小时。原 viewer 的四季按钮及 1900–2100 任意日期入口不放在实时主流程中。

“现在”由服务端创建视图时解析。拖动到未来立即标为预报，选择历史标为回看。日期标签显示上海本地日期，跨零时明确换日；辐射均值显示例如“14:00–15:00 平均”，不缩写成瞬时 14:30。

### 6.2 拖动、播放与切换

拖动时先预览目标时间标签；松开后请求视图，可对连续输入做约 250 ms 防抖。新时间未提交时保留当前图层与其真实时间标签，不先把旧色带标成新时间。首版仅在已缓存的连续可用帧间播放，缺帧时暂停并显示缺失，不用前一帧伪装。

每次选择生成递增请求序号，取消旧请求；即使取消失败，也只接收当前序号对应响应。先准备新 view_id 的图层、图例与必要点读数，达到当前视口可显示条件后整体切换。后续平移加载的瓦片仍必须来自该 view_id 版本；部分未加载区域明确留空。

前端约每 60 秒条件轮询场景状态，页面隐藏暂停。用户停留“现在”且未在拖动/播放时，发现新发布版本后准备并切换；固定历史或未来视图不强行跳回现在，只提示有新预报。恢复标签页时先刷新状态与权限，再决定重新创建视图。

视图到期返回 410 时整体重建；重建未完成保留旧画面但停用过期查询，不混用新旧读数。天气更新失败时继续显示旧成果与过期提示。

## 7. 地点详情与图表

地点详情按“位置 → 当前变量与有效时间 → 其他环境变量 → 逐时变化 → 附近体感 → 来源方法”组织。

主读数同时显示单位和“当前估计/预报/回看”。没有数据时写明“该位置无覆盖”等具体原因，不显示 0。可展开来源尺度、接收高度、数据版本与物理量定义；宏观净短波和局地下行短波使用不同名称。

时间序列图使用同一 view_id 的 series 接口。首版每次查看一种变量，可切换；单位不同的量不共用一个轴。缺测断线，区间平均值按区间表达，不使用平滑曲线暗示分钟级观测。图表点选只能跳到支持的时刻，并走同样版本切换流程。提供数据表视图和表格导出。

建筑/树冠详情优先展示名称、类型、高度与高度来源，原始属性放折叠区。附近体感按独立体验时间筛选；用户正在浏览未来时，仍清楚写“近期实际提交的体验”，不称未来体感预测。

## 8. UGC 交互闭环

### 8.1 入口与表单

地图常驻“记录体感”，地点卡片提供“记录此处体感”。匿名用户可先填写，提交前完成登录；登录后保留草稿。定位只在用户主动操作时请求，拒绝后支持地图选点或手动输入合法坐标。

表单分为三个连续区块，不强制每区跳一页：

1. 地点与体验时间：显示标记、地址/坐标、定位来源，默认真实现在而非未来时间轴时刻。
2. 体感与场景：冷热必选，舒适可选，室内外、活动、日晒独立填写；不默认选择“中性”或“阴影”。
3. 补充与公开范围：文字、私密/公开、公开位置精度确认；粗化公开时预览公开网格及标记位置。

表单字段与枚举以[接口文档](后端应用接口层_详细设计.md)为准。照片能力为 false 时不显示可点击上传按钮。体验时间允许历史记录，环境不能配对时明确说明但允许提交。

### 8.2 提交、失败和冲突

同一逻辑提交持有同一个幂等键。网络超时后用原正文与原键重试；修改正文后使用新键，不能自动把已成功但响应丢失的提交变成第二条。后端返回成功后显示记录与“环境待匹配/已匹配/未匹配”，不将匹配失败显示为打卡失败。

草稿默认仅保存在当前页面内存，不把精确位置和文本写入 URL 或共享持久缓存。关闭有修改的表单前提供保留当前编辑或放弃的明确选择；退出登录清除私密状态。刷新丢失草稿属于首版限制，应在存在未提交修改时提示。

本人记录支持编辑、可见范围修改与删除。编辑携带 revision；412 时展示“记录已在其他窗口更新”，保留本地修改供比较，不能自动覆盖。删除需明确确认；成功后移除地图、列表与聚合缓存，并刷新相关导出状态。

“我的记录”按体验时间列表展示，可查看发布时间及匹配状态。公开详情不得请求或缓存本人完整字段；切换账号清空私密查询缓存。

## 9. 响应式与可访问性

| 可用宽度 | 布局 |
| --- | --- |
| ≥1280 px | 三栏；左右均可收起，地图保持最大可用区域 |
| 768–1279 px | 左栏收为工具入口；右侧详情作为可收起面板，避免两栏同时挤压地图 |
| <768 px | 地图铺满剩余视口；顶部搜索与模式，底部紧凑时间条；图层/详情/表单共用底部抽屉，同一时刻只展开一个 |

移动端抽屉提供收起、半屏与近全屏三档，并有可点击替代操作，不能只允许拖拽。编辑时软键盘顶起表单，提交按钮可见；使用动态视口与安全区，时间条和定位按钮不被系统底栏遮挡。横屏低高度时折叠时间轴为时间按钮。

触控目标至少 44×44 px；键盘可遍历搜索、图层、时间、详情和表单。地图提供可聚焦控制及按键说明，鼠标悬停信息同时可通过点击/焦点获得。对话框锁定焦点，关闭后返回触发控件；Esc 可关闭普通面板，但未提交表单先处理放弃确认。

加载与提交状态使用节制的 aria-live 通知，不逐帧播报时钟。遵循 prefers-reduced-motion，关闭自动相机飞行及风粒子播放；动画默认不自动启动。地图外提供当前位置读数和列表，不能要求用户只能识别三维颜色才能完成任务。

## 10. 前端模块与状态结构

设计目录位于新平台工程；目前已存在 Vue 前端及部分模块，以下保留目标划分，实际实现进展见第 14 节：

```text
frontend/src/
  app/                 页面外壳、路由、登录边界
  features/scene/      三维生命周期、相机、选择与图层适配
  features/environment/ 时间轴、视图切换、读数、图表
  features/check-ins/ 表单、公开列表、聚合、本人记录
  features/export/    地图导出与后端任务
  services/           API 客户端、错误映射、请求取消
  stores/             场景、环境选择、会话、界面状态
  components/         面板、图例、控件与状态提示
  styles/             token、布局、响应式与可访问性
```

| 状态域 | 关键内容 | 禁止混入 |
| --- | --- | --- |
| scene | scene_id、场景版本、相机、可见图层、选中对象 | 后端科学计算的可变参数 |
| environment | committed_view、pending_view、请求序号、模式、图例、播放状态 | UGC 体验时间 |
| check-ins | 公开筛选、本人数据、表单草稿、幂等键、修订 | 公共 URL 或其他账号缓存 |
| session | 登录状态、身份、权限 | 供应商密钥或脚本可读会话 Cookie |
| ui | 面板、抽屉、忙碌状态、可访问性偏好 | 完整大型三维模型 |

Cesium 实例和大型模型保持在适配器内部，避免进入深度响应式树。卸载时释放事件、计时器、GPU 资源与网络请求。scene_id 变化后中止旧场景请求并清理旧选中对象；图层可见性变化不销毁整个地图。

API 客户端统一处理 401、412、410、429 等；受控重试尊重 Retry-After。写请求只有保留幂等语义才重试。登录失效不丢失当前表单，重新登录后再提交。

URL 可保存公开 scene_id、变量和所选时间；不保存私密坐标、表单文字或会话信息。私密详情不生成公共分享链接。公开固定视图链接到期时先说明失效，再由用户选择建立新视图。

## 11. 性能、失败与部署资源

继承 Cesium 的按需渲染策略；仅在相机、图层、时刻或动画变化时请求渲染。时间轴按小时成果缓存，最多预取相邻少量帧，不预加载全上海所有资源。UGC 平移结束后按 bbox 查询，低缩放显示聚合，避免每帧请求。

性能降级顺序建议为关闭风粒子、降低视觉阴影质量、降低设备像素比、减少三维细节。降级不改变后端数值或默默隐藏缺测。GPU 上下文丢失时尝试重建，失败后保留列表、查询表单与 UGC；不让整页变成空白。

场景资源、环境和 UGC 分别加载，界面壳先可操作，不用一个全屏 loading 等待所有在线建筑到齐。外部建筑不可用时显示已就绪地形与要素并注明缺失。

Cesium 浏览器资源令牌与服务端天气密钥分开处理。原 viewer 的本机 `/api/cesium-token` 机制不能照搬到公网；公开客户端令牌需限制资源和来源，天气密钥绝不进入前端。来源署名始终可见。

首版性能验收记录设备、浏览器、视口、网络、可见几何规模和操作响应；不在未测量时保证全市流畅或固定 FPS。

## 12. 导出交互

地图工具提供“导出当前专题地图”，先冻结相机、图层、view_id、时间和图例，等待该视口资源就绪。导出 PNG 及打印/PDF 布局包含标题、比例尺、指北、有效时间、单位、图例、来源与状态说明；透视图无法提供统一比例尺时注明局部比例尺参考位置，优先提供俯视制图模式。

截图不能仅截 WebGL canvas 而遗漏图例、UGC 或署名；DOM 叠加层需纳入合成或导出布局。跨域资源导致 canvas 不可导出时明确报错并提供允许的俯视/表格导出，不能下载空白图片后提示成功。

导出中 UGC 默认只含公开可见投影，私人记录须单独明确选择且遵守本人权限。专题导出携带实际数据时间与过期状态，不去掉警示后包装成实况。表格导出调用后端 `/exports`，显示任务状态、失败与到期下载。
