# 一键启动前后端

在 Windows 中双击本目录的 `start.bat`，等待窗口显示前端地址后访问。默认端口空闲时地址为：

- 前端：<http://127.0.0.1:5178/?mode=api>
- 后端接口文档：<http://127.0.0.1:8000/docs>

默认端口被占用时，脚本会向后查找最多 100 个端口，选择空闲端口并自动同步前端代理。例如 8000、5178 被占用时，可改用 8001、5179；**以启动窗口打印的地址为准**。显式传入 `-BackendPort` 或 `-FrontendPort` 时严格使用指定端口，被占用则报错。

保留启动窗口，按 **Ctrl+C** 停止本次启动的前后端。脚本不会终止占用端口的其他进程。服务启动失败或运行中退出时，脚本会清理本次启动的服务。

默认使用真实后端模式，启动进程内覆盖前端演示配置，并配置 Vite 到后端的代理；不改写 `.env`。启动成功仅表示服务可访问，不代表前后端全部接口契约和真实数据已经联调通过。

## 首次运行条件

- 安装 Node.js（版本满足前端 Vite 7 要求）和 Python，PostgreSQL 服务及后端数据库配置可用。
- Python 按顺序查找 `backend/.venv`、平台目录 `.venv`、上级项目目录 `.venv`，最后使用 PATH 中的 `python.exe`。
- 缺少依赖时，在前端目录执行 `npm ci`；使用选定的 Python 执行 `python -m pip install -r backend/requirements.txt`（此命令从平台目录执行）。脚本不会自动安装依赖。
- 后端已有 lifespan 启动逻辑会初始化平台 schema、表及种子数据，并按所选供应商检查、更新天气发布。脚本不额外运行数据库初始化命令。数据库配置沿用后端现有设置。

## 可选命令

从本目录打开 PowerShell：

```powershell
# 仅检查解释器、依赖和端口，不启动服务或连接数据库
.\start.ps1 -Check

# 使用其他端口，同时自动调整前端代理
.\start.ps1 -BackendPort 8001 -FrontendPort 5179

# 显式指定已有 Python 环境
.\start.ps1 -PythonPath '..\.venv\Scripts\python.exe'

# 合成演示前端，仍同时启动后端
.\start.ps1 -Demo

# 启动并检查两个 HTTP 服务就绪，随后自动停止
.\start.ps1 -VerifyStartup
```

上述参数也可传给 `start.bat`。若 PowerShell 的脚本策略阻止直接执行 `.ps1`，使用 `start.bat`；它只为当前启动进程设置执行策略。

每次启动的标准输出和错误日志分别保存到 `logs/<启动时间>-<进程号>/`。后端最长等待 120 秒，随后启动并检查前端。日志不进入版本库；其中可能含后端错误详情，分享前检查敏感信息。

和风天气 JWT 配置见 [后端和风天气配置](和风天气配置.md)。完成 `backend/.env` 配置后重启即可选择该供应商，私钥不放在前端环境变量中。

本脚本用于本机开发，不自动打开浏览器，也不承担数据库安装、生产部署或接口适配。

## 数据库未启动

若日志显示连接 `127.0.0.1:5432` 被拒绝，检查 `postgresql-x64-16` 服务。在**管理员 PowerShell** 中运行：

```powershell
Start-Service postgresql-x64-16
```

然后重新双击 `start.bat`。`-Check` 只检查依赖与端口，不代表数据库可用。2026-09-17 本次排障实测该服务为 Stopped，当前普通权限无法启动；自动避开端口的检查已通过，完整启动验证受数据库未运行阻塞。
