# 后端应用接口层：详细设计

日期：2026-09-16；版本：v0.1；状态：设计草案，尚未实现、部署或完成接口测试。

所属层次：[五层架构](系统分层与模块架构.md)第二层。计算结果遵循[环境计算层设计](环境计算与空间分析层_详细设计.md)，辐射能力受[降尺度方案](太阳辐射物理降尺度方案.md)约束。本文独立维护平台接口，不修改研究项目数据字典。

## 1. 职责与技术安排

这一层负责把“打开地图、切换时间、查询位置、记录体感”转成可执行、可校验的业务请求。外部天气获取由接入层负责，遮挡与辐射批量计算由计算层负责；地图浏览复用已发布成果。

建议首版采用 FastAPI + Pydantic 定义 REST/JSON 接口并生成 OpenAPI，部署为单个后端应用。PostGIS 为采用的数据库，耗时工作交给后台任务进程。以上为本轮技术建议；**本机 PostgreSQL 16.15 + PostGIS 3.6.2 已于 2026-09-16 实测可用**（详见[平台代码评审报告](平台代码评审报告_20260916.md)），但本文档描述的是设计契约，不代表各接口已按规定实现——实测符合度见该报告。

后端内部按路由与输入校验、应用服务、数据访问/任务适配器组织。权限、日志和错误处理统一实现；接口不直接依赖某个供应商响应格式。

## 3. 公共契约

### 3.1 路径、格式与时间空间

- 路径统一以 `/api/v1` 开头，下表省略此前缀。JSON 字段采用 `snake_case`，资源 ID 是不透明字符串。
- 普通成功响应为 `{ "data": ..., "meta": { "request_id": ..., "server_time": ... } }`；删除成功返回 204 空响应。瓦片、文件、304 响应按各自协议处理，不包 JSON。
- 时间输入必须为带时区的 RFC 3339；输出统一 UTC `Z`，前端转为 Asia/Shanghai。筛选区间使用 `[start, end)`；历史研究“含结束日期”需先换算为次日零时上界。
- 经纬度及 GeoJSON 统一 EPSG:4326，经度在前、纬度在后；`bbox` 为西、南、东、北。首版仅接受不跨日期变更线的合法上海场景范围。
- 定位上报明确坐标来源；GCJ-02 在经过测试的输入适配环节转换为 WGS84，转换版本和原始坐标由受限存储保留。公共接口的 `location` 不接收未声明体系的混合坐标。
- 缺失值为 `null`，同时提供原因；禁止用 0、空字符串或特殊数值充当缺测。
- 列表采用 `limit` 和不透明 `cursor`，默认 50、最大 200。按时间与 ID 稳定排序；游标绑定筛选条件和访问范围，变更条件后重新查询。

### 3.2 状态不混成单一枚举

| 维度 | 拟定字段和值 | 含义 |
| --- | --- | --- |
| 产品能力 | `availability`: available / missing / unsupported | 有产品、暂缺产品、输入不支持此计算 |
| 输入新鲜度 | `freshness`: fresh / stale / unknown | 根据该产品刷新策略判断，不仅比较获取时间与有效时刻 |
| 更新过程 | `update_state`: idle / queued / running / failed | 后台是否正在更新；可与旧成果同时存在 |
| 单项取值 | `value_status`: valid / no_data / outside_coverage / incompatible | 一个位置和时刻能否获得该变量 |
| 展示模式 | `mode`: current_estimate / forecast / historical | 当前估计、未来预报、历史回看；不据此称为实测 |

历史产品的新鲜度不能按“距现在很久”判断；预报有效时间尚未到来也不能证明起报批次足够新。产品清单给出判断策略与时间依据。

## 4. 场景与图层接口

| 方法与路径 | 主要输入 | 输出与规则 |
| --- | --- | --- |
| GET `/scenes` | 分页 | 已配置场景的 ID、名称、边界、可用状态 |
| GET `/scenes/{scene_id}` | 场景 ID | 边界、初始视角、展示时区、默认图层、UGC 与环境覆盖范围 |
| GET `/scenes/{scene_id}/layers` | 无 | 图层 ID、类型、空间版本、资源清单、署名、许可、覆盖、拾取能力 |
| GET `/scenes/{scene_id}/places` | `q`、可选 `bbox`、分页 | 场景内已导入 POI 的搜索结果；首版不默认新增外部地理编码调用 |
| GET `/scenes/{scene_id}/features` | `layer_id`、`bbox`、分页 | 限定范围的轻量要素；高密度图层由瓦片加载 |
| GET `/scenes/{scene_id}/features/{feature_id}` | `layer_id`、`layer_version` | 对应版本的建筑、树冠、道路等对象属性及来源 |

静态资源地址从后端登记的资源清单产生，不允许客户端提交任意文件路径或上游 URL 让后端代理。瓦片 URL 的坐标体系、编码、NoData、版本和有效期由清单声明；图例色带端点不作为数值有效范围截断依据。

## 5. 环境探索接口

### 5.1 能力、版本与视图

| 方法与路径 | 输入 | 输出 |
| --- | --- | --- |
| GET `/scenes/{scene_id}/environment/catalog` | 无 | 产品与变量、单位、物理定义、可用时间、能力限制、覆盖和发布状态 |
| GET `/scenes/{scene_id}/environment/releases` | `product_id`、分页 | 已发布版本、来源批次、有效时间范围、计算时间 |
| POST `/scenes/{scene_id}/environment/views` | 变量列表、时间选择、版本选择策略 | `view_id`、实际选中版本与时刻、图层地址、各项状态 |
| GET `/environment/views/{view_id}` | 无 | 固定视图的清单及当前新鲜度；不静默换版本 |
| GET `/environment/views/{view_id}/point` | `longitude`、`latitude` | 视图各变量的同版读数、来源与质量 |
| GET `/environment/views/{view_id}/series` | 位置、起止时间、变量 | 视图绑定版本内的序列；缺测保留为空 |

视图是轻量的服务端结果选择记录，创建视图不触发天气采购或批量计算。请求的 `time_selection` 必须二选一：`{ "kind": "now" }` 或 `{ "kind": "at", "time": "..." }`。`now` 只在创建时解析一次，保存 `requested_time`；前端需要新“现在”时重新创建视图。

`release_selection` 支持 `latest` 或 `pinned`；后者附 `release_ids` 显式指定产品版本。`latest` 选取创建时最新已发布版本，再将选择固定。每项返回 `requested_time`、`resolved_time` 或 `interval_start/end`、`temporal_support`、时间选取方法和与请求时间的偏移。相邻小时选择的最大容许偏移由产品清单声明，不静默选取相距很远的时刻。

首版优先发布产品真实支持的小时/区间值；某产品明确支持时间插值时才能选择该方法。小时平均辐射必须返回其区间，不能伪装成点时刻值。不同产品不能对齐时可分别展示并返回实际时间，合成计算则返回 `incompatible`。

视图响应的每项包含 `product_id`、`variable`、`release_id`、`unit`、`availability`、`freshness`、`reason_code`、`assets` 和 `provenance`。后者包含源版本、空间支持尺度、模型版本与省略项。仅有净短波时，局地下行短波为 `unsupported`，宏观净短波与几何阴影仍可用。

### 5.2 固定视图的生命周期

`view_id` 同时绑定渲染、点查询和导出，不能作为读取私密资源的授权凭据。视图响应返回 `expires_at`，首版建议会话视图保留 24 小时，配置可调。到期返回 410，前端重新创建后整体切换，不在旧图层上显示新版本读数。

底层成果保留策略与视图有效期协调；被 UGC 配对或导出引用的来源与数值需持久保存，不依赖短期视图缓存。新结果发布后已有视图仍指向旧版；新鲜度可以变为过期，数据内容与版本不能改变。

空间取值使用已发布栅格或相同版本、方法的查询器，不能从屏幕色彩反推。点查询返回的 `value` 为空时附 `value_status` 和 `reason_code`。合法请求的局部缺测返回 200 和各项状态；版本不存在、权限不足、请求非法分别使用 HTTP 错误。

### 5.3 请求示例

以下均为接口示意，场景 ID、时间和位置不是已部署资源或实测结果。

```json
{
  "variables": ["air_temperature", "relative_humidity", "net_shortwave_background"],
  "time_selection": {"kind": "now"},
  "release_selection": {"mode": "latest"}
}
```

变量代码由 catalog 提供；建议分别使用 `net_shortwave_background` 与 `local_downwelling_shortwave`，避免混用净短波和下行短波。规范化单位初步采用 °C、相对湿度 %、风速 m/s、风向 degree、辐照度 W/m²；供应商原始单位与归一化过程保留在来源元数据中。

## 6. UGC 接口与记录结构

### 6.1 接口清单

| 方法与路径 | 权限 | 主要行为 |
| --- | --- | --- |
| POST `/check-ins` | 已登录 | 创建本人记录；要求 `Idempotency-Key`；201 返回记录与匹配状态 |
| GET `/check-ins` | 公开 | 仅返回公开且允许展示的记录；要求场景、bbox、体验时间区间 |
| GET `/check-ins/aggregates` | 公开 | 指定场景、bbox、体验时间区间和允许的网格尺度；返回数量与构成 |
| GET `/check-ins/{check_in_id}` | 公开或所有者 | 分别返回公开投影或本人完整字段 |
| GET `/me/check-ins` | 已登录 | 本人分页记录，含私密、待展示与匹配状态 |
| PATCH `/check-ins/{check_in_id}` | 所有者 | 部分更新；要求 `If-Match` 修订号；修改后重新检查展示资格 |
| DELETE `/check-ins/{check_in_id}` | 所有者 | 要求 `If-Match`；204；立即从公开读取、聚合与后续导出排除 |
| POST `/check-ins/{check_in_id}/reports` | 已登录 | 提交不当内容反馈；要求幂等键；不向举报者泄露私密详情 |

### 6.2 创建请求

```json
{
  "scene_id": "scene_demo",
  "location": {
    "type": "Point",
    "coordinates": [121.47, 31.23]
  },
  "location_source": "manual_map",
  "horizontal_accuracy_m": null,
  "experienced_at": "2026-09-16T14:00:00+08:00",
  "time_source": "user_selected",
  "time_uncertainty_minutes": null,
  "thermal_sensation": "hot",
  "thermal_comfort": null,
  "setting": "outdoor",
  "activity": "walking",
  "sun_exposure": "shade",
  "note": "树荫下步行时仍觉得热。",
  "visibility": "public",
  "public_location_precision": "grid_200m"
}
```

该示例为虚构表单；请求体不能指定 `owner_id`、审核状态、发布时间或环境匹配值，服务端从会话及业务流程生成。

| 字段组 | 约束 |
| --- | --- |
| 地点 | 必须为合法点且在该场景允许打卡范围内；手动选点精度未知可为空，不推断为 GPS 精度 |
| 时间 | 体验时间必填；首版允许不超过服务端当前时刻 5 分钟的设备误差，保留原值；更远未来时间拒绝；历史记录不因缺环境而拒绝 |
| 热感觉 | 必选 `cold / cool / neutral / warm / hot`，对应冷、凉、中性、偏热、很热；缺失不得默认中性；它是产品自报量表，不直接映射历史社媒分类 |
| 舒适 | 可空；`comfortable / ordinary / uncomfortable`，独立于热感觉 |
| 场景 | `indoor / outdoor / mixed / unknown`；活动及日晒可空，不预选事实 |
| 文本 | 可空，首版最多 1000 字符；以纯文本存储和安全渲染，不接收 HTML |
| 可见性 | 必须显式选择 `private / public`；公开时必须确认公开位置精度 |

原始设计的照片功能保留为后续能力；首版 `capabilities.media_upload=false`，表单不显示可用上传入口。本轮不设计未经处理直接公开照片的捷径。

### 6.3 幂等、修订与匹配

创建、举报和导出按“用户 + 路由 + 幂等键”去重，首版键保留 24 小时；相同键和相同请求体返回原资源，相同键但请求体不同返回 409。并发请求通过持久唯一约束或等效事务保证仅创建一次，不依赖浏览器禁用按钮。

记录响应带 `revision` 和 ETag。PATCH/DELETE 缺少 `If-Match` 返回 428，修订不匹配返回 412；前端重新加载后由用户合并修改。PATCH 中字段省略表示不修改，显式 null 仅允许清空可选项。

打卡保存与“待匹配事件”在同一事务中持久化，后台可重试消费。匹配状态为 `pending / matched / unmatched / failed`；缺少历史环境为 unmatched，执行异常为 failed。环境不可用仍返回打卡创建成功。

修改位置、时间或室内外属性后生成新的匹配修订；任务提交结果前核对当前修订号，旧任务不能覆盖新匹配。删除后旧任务不得恢复记录。配对引用具体环境版本而非可变 latest 指针。

### 6.4 公开位置与公开字段

首版拟提供 `exact` 与 `grid_200m` 两种公开位置方式；精确公开必须明确确认。200 m 网格在 EPSG:32651 中按固定原点生成，以网格中心转回 WGS84 展示，返回粗化类型和尺度。这是隐私粒度，不保证匿名，也不是观测定位精度。

公开列表、详情、bbox 筛选、聚合、导出均使用同一公开几何，避免通过不同接口反推出原始点。公开返回别名、体验信息与公开位置；不返回账号标识、原始定位精度、私密备注或精确配对位置。精确环境配对及可能推断位置的细尺度结果首版仅本人可见。

`visibility`、`publication_status` 与 `match_status` 分别保存。公开查询仅含 visibility=public 且 publication_status=published 的记录。首版采用有限测试账号及基础内容校验；被标记内容进入待处理状态，运营通过受限管理流程处理。修改公开文本后重新检查，旧版不得持续公开。

聚合在公开网格上统计记录数和各类热感觉计数，不能解释为人流标准化热抱怨率。首版查询区间最多 31 天、网格最多 5000 个，超限要求缩小范围或加粗尺度，不静默截断。

## 7. 身份与权限

| 方法与路径 | 行为 |
| --- | --- |
| POST `/auth/login` | 账号密码登录，成功创建服务端会话；失败消息不泄露账号是否存在 |
| POST `/auth/logout` | 撤销当前会话，204 |
| GET `/auth/session` | 返回是否登录、本人 ID/别名和权限；不返回密码或凭据 |

建议首版预置两名独立测试用户，关闭公开注册；身份方案仍可在实施时替换，但所有权规则不变。密码使用成熟库的强密码哈希保存，不写入文档或仓库。浏览无需登录；创建与个人管理需登录；运营权限与普通用户分开，不能由请求体自报。

推荐前后端同源部署，使用 HttpOnly、Secure、SameSite 会话 Cookie；涉及状态变更的请求校验 CSRF token 与 Origin，登录也校验可信来源。会话登录时轮换、退出时撤销，首版有效期建议 12 小时。跨源部署仅允许明确来源，不能以通配 CORS 配合凭据。

资源读取、修改、任务查询与下载每次校验权限。对不可见私密对象统一返回 404。任何用户不能通过更换 ID 编辑他人记录、查看他人导出或访问全局内部任务。

## 8. 更新状态与后台任务

| 方法与路径 | 权限与用途 |
| --- | --- |
| GET `/scenes/{scene_id}/status` | 公开；产品版本、新鲜度、上次成功时间、更新状态和安全的原因码 |
| GET `/tasks/{task_id}` | 发起者或运营；排队/运行/成功/失败/取消状态及可用进度 |

首版前端约每 60 秒条件轮询场景状态，页面不可见时暂停；不是每 60 秒请求供应商。使用 ETag/If-None-Match，无变化返回 304。暂不要求 WebSocket；未来可按相同状态契约增加推送。

普通用户不能请求全市重算、强制刷新供应商或指定任意计算参数。产品更新由调度系统执行；人工重跑先采用服务端受控运维入口。任务进度不能估计时返回 null，不伪造百分比。公开状态不暴露内部路径、凭据或堆栈。

## 9. 导出契约

| 方法与路径 | 行为 |
| --- | --- |
| POST `/exports` | 已登录；幂等创建异步任务，202 返回 export_id 与 task_id |
| GET `/exports/{export_id}` | 所有者查询状态、格式、来源版本、有效期与下载入口 |
| GET `/exports/{export_id}/download` | 再次校验权限及资源可见性后下载；过期返回 410 |

首版类型：`environment_table`（CSV，最多 10000 个服务端限定范围内点时刻）、`my_check_ins`（CSV/GeoJSON）、`public_check_ins`（CSV/GeoJSON，最多 10000 条）。超过限制返回 422，不静默截断。环境导出必须指定 view_id 和合法时空范围，禁止借导出触发新的供应商请求。各来源的可导出能力由许可配置控制，展示权限不自动等于可批量再分发权限。

CSV 使用 UTF-8-SIG，对用户文本实施电子表格公式注入防护，并记录导出编码规则。文件附清单，说明 CRS、单位、时间、环境版本、模型方法、缺测与署名。建议文件有效期 24 小时；有效期不替代权限校验。

UGC 导出记录其依赖记录及修订；删除、转私密或公开位置改变后，使受影响旧导出失效，下载时再次检查。已经由用户下载的文件无法远程收回，不承诺可撤回所有外部副本。

专题地图由前端按固定 view_id 生成 PNG/PDF，保留图例、比例尺、时间、来源和当前可见图层；后端供给必要元数据。首版不部署服务端三维截图浏览器。地图导出仍属于系统验收，后续前端文档细化实现。

## 10. 错误、缓存与资源限制

错误体采用 `{ "error": { "code": "...", "message": "...", "details": [] }, "meta": { "request_id": "..." } }`。code 供程序判断，message 面向用户，details 仅返回安全字段校验信息。

| HTTP | 使用场景 |
| --- | --- |
| 400 | 无法解析的请求 |
| 401 / 403 | 未登录 / 已登录但无该操作权限 |
| 404 | 不存在或当前用户不可见 |
| 409 | 幂等键内容冲突、发布状态冲突 |
| 410 | 视图、历史成果或下载已到期，不自动替换版本 |
| 412 / 428 | 修改修订冲突 / 未提供修改前置条件 |
| 422 | 字段、时空范围或数量不合法 |
| 429 | 请求频率超限，附 Retry-After |
| 503 | 核心读取/写入依赖不可用，附可重试信息 |

天气刷新失败但仍有可读旧成果时返回 200 和过期/更新失败状态；数据库不可用导致打卡未持久化时返回错误，不谎报提交成功。

稳定的公开环境成果可按版本缓存；catalog/status 使用短缓存与条件请求。登录、个人记录、任务、UGC 与含 UGC 的下载使用 private/no-store，公开 UGC 首版也不做长效 CDN 缓存，保证隐藏与删除及时生效。服务端内部聚合缓存依赖记录修订，修改后失效。

初始可配置限额：点查询每会话/IP 每分钟 120 次；打卡每用户每分钟 10 次；登录每账号与 IP 每 15 分钟 5 次失败后退避；导出每用户同时最多 2 个任务；时间序列最多 240 个原始时步。共享网络场景分别考虑账号和 IP，不用单个 IP 限额误伤全部用户。具体延迟目标待代表性场景基准测试后确定，不将设计目标写成性能实测。

记录 request_id、耗时、状态码、任务/结果版本及必要操作审计；密码、Cookie、令牌、全文打卡内容及精确坐标不进入普通访问日志。

## 11. 首批开发顺序与接口验收

1. 公共响应、会话与场景目录；先提供明确标识的开发 fixture，不混入正式环境。
2. 环境 catalog、固定视图、图层加载与同版点查询，再补时间序列与更新状态。
3. UGC 创建、本人管理、公开投影、聚合与后台匹配闭环。
4. 导出、异常恢复、限流和权限回归。

| 场景 | 应达到的可核验行为 |
| --- | --- |
| 后台发布新版时用户点选旧地图 | 图层与查询仍为旧 view_id 所指定版本 |
| 净短波可用但缺 GHI/DNI/DHI | 宏观背景可显示，局地辐射明确 unsupported |
| 同一键并发提交两次打卡 | 仅持久化一条；不同正文复用该键返回 409 |
| 修改时另一个窗口已更新 | 返回 412，不覆盖较新修订 |
| 气象缺失或匹配进程重启 | 打卡保存成功；任务可恢复，状态不冒充 matched |
| 删除或改为私密 | 公开详情、列表、聚合与旧导出均不能继续泄露该记录 |
| 粗化位置后进行 bbox 查询 | 以公开几何筛选，不能探测真实坐标 |
| 旧匹配任务晚于新修订完成 | 丢弃旧修订结果，不覆盖新的配对 |
| 跨上海午夜及历史回看 | 体验时间、有效区间、页面模式保持一致 |
| 猜测他人的对象或任务 ID | 无权读取、修改或下载 |
| 超范围、过期或局部缺测 | 分别显示合理错误/质量状态，不能一律返回零 |

本轮产物是接口契约草案。后续实现时以 OpenAPI 与实际契约测试核验，不声称本文件已建立服务或完成任何实测。
