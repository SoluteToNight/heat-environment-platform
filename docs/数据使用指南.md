# 平台数据使用与跨设备迁移指南

本文档介绍 **城市热暴露时空可视分析平台 (Heat Environment Platform)** 所需的数据结构、内置数据包、使用模式及在另一台设备上快速恢复运行的完整步骤。

---

## 1. 数据架构与图层分工

平台采用双层数据组织架构：**业务应用层 (`platform` Schema)** 与 **基础客观地理空间层 (`public` Schema)**。

### 1.1 业务应用层 (`platform` Schema)
由后端 SQLAlchemy 模型维护，记录系统运行状态与动态人居交互：
- `platform.scenes`：场景元数据（场景ID、中心经纬度 `[121.4737, 31.2304]`、BBOX范围与状态）。
- `platform.users` / `user_sessions`：系统预设账号（`user_test`、`admin_test`）及安全鉴权会话。
- `platform.env_releases` / `weather_records`：逐小时气象环境指标发布批次（包含气温 `temperature_2m`、湿度 `relative_humidity_2m`、风速风向、太阳总辐射 `shortwave_radiation`、直射与散射辐射）。
- `platform.env_views`：前后端联动渲染的高效快照缓存。
- `platform.ugc_check_ins`：公众与研究员热感觉体感打卡记录（支持精确坐标与200m网格脱敏坐标、热感觉投票、室内外环境情境、遮阳情况及气象环境要素自动匹配）。
- `platform.system_tasks` / `export_records`：异步分析任务与专题数据导出归档。

### 1.2 基础客观地理空间层 (`public` Schema)
提供三维地图底座与热环境影响要素：
- `public.base_admin_boundary`：上海市域边界及 16 个行政区划矢量多边形（EPSG:4326，附带 UTM 投影面积 `area_km2` 与中心城区标识）。
- `public.osm_buildings`：建筑矢量底面与空间高度形态（包含名称、建筑类别、绝对高度 `height_m`、地上楼层 `levels`、基底面积 `area_m2` 与估算体积 `volume_m3`，支持 Cesium 3D 白模挤出渲染）。
- `public.osm_roads`：分级路网要素（包含道路名称、道路等级 `highway`、表面类型与长度 `length_m`）。
- `public.osm_water`：水系水体多边形（黄浦江、苏州河等）。
- `public.osm_green`：公园绿地与游憩绿化要素。
- `public.osm_poi`：公共服务设施、商圈与热力聚集兴趣点。

### 1.3 静态栅格与控制点资产
- **空间同化控制点**（`backend/app/data/shanghai_*_points.json`）：用于数值预报向 500m 分辨率多源同化插值计算。
- **DEM 晕渲底图**（`frontend/public/layers/shanghai_dem_hillshade.*`）：提供 12.5m 分辨率上海地表立体起伏纹理。

## 2. 平台支持的两种运行模式

平台根据目标设备的环境具备 **双模式运行能力**：

| 运行模式 | 适用场景 | 依赖项 | 启动命令 |
| :--- | :--- | :--- | :--- |
| **Demo 模式 (前端独立体验)** | 快速向导师汇报演示、无 PostgreSQL 数据库的临时笔记本、纯界面交互体验 | 仅需 Node.js | `.\start.ps1 -Demo` 或前端运行 `npm run dev` |
| **Full-Stack 模式 (全栈正式环境)** | 完整分析计算、UGC 打卡入库、逐时气象动态拉取、多源数据导出与模型分析 | Python 3.10+、Node.js 18+、PostgreSQL 14+ & PostGIS 3+ | `.\start.bat` |

> **提示**：在 Demo 模式下，前端自动加载合成演示数据与本地 Mock 数据，具备完整的 Cesium 三维交互、体感打卡、图层切换和图表呈现能力，零数据库依赖即可流畅运行。

## 3. 在新设备上快速搭建与数据导入（全栈模式）

### 第一步：克隆/复制代码到新设备
通过 Git 将代码克隆到新设备：
```bash
git clone git@github.com:SoluteToNight/heat-environment-platform.git
cd heat-environment-platform
```

### 第二步：一键运行环境初始化脚本
在平台根目录下运行环境搭建脚本（脚本会自动创建 Python 虚拟环境、安装后端依赖及前端 npm 包，并创建默认 `.env` 配置文件）：
- **Windows (PowerShell)**：
  ```powershell
  .\setup_env.ps1
  ```
  *(或直接双击运行 `setup_env.bat`)*
- **Linux / macOS**：
  ```bash
  chmod +x setup_env.sh && ./setup_env.sh
  ```

### 第三步：配置数据库连接
1. 确保新设备已安装 PostgreSQL 并已安装 PostGIS 扩展；
2. 打开 `backend/.env`，修改 `DATABASE_URL` 为新设备上的本地数据库口令：
   ```dotenv
   DATABASE_URL=postgresql://postgres:你的数据库密码@127.0.0.1:5432/gis_thermal_shanghai
   ```
3. 如需使用在线高精度卫星底图，可在 `frontend/.env` 和 `backend/.env` 中填入你的天地图 Key：
   ```dotenv
   TIANDITU_KEY=你的天地图密钥
   VITE_TIANDITU_KEY=你的天地图密钥
   ```

### 第四步：一键导入内置数据包
在平台根目录下运行数据库初始化脚本：
```powershell
& .\.venv\Scripts\python.exe scripts\init_database.py
```
该脚本会自动：
1. 检测并创建 `gis_thermal_shanghai` 数据库；
2. 激活 `postgis` 空间扩展；
3. 执行 `data_package/01_platform_seed.sql` 建立全部业务表并写入初始种子数据；
4. 执行 `data_package/02_public_admin_boundary.sql` 导入上海市界与 16 区边界；
5. 执行 `data_package/03_public_spatial_core_sample.sql` 导入上海核心示范区（外滩、陆家嘴、人民广场、静安寺区域）8,000 座 3D 建筑、5,000 条道路、水体与绿地要素；
6. 自动验证各表导入行数。

### 第五步：一键启动平台
双击运行平台根目录下的 `start.bat`（或在 PowerShell 中执行 `.\start.ps1`）：
- 后端服务：`http://127.0.0.1:8000`（Swagger 接口文档：`http://127.0.0.1:8000/docs`）
- 前端交互界面：`http://127.0.0.1:5178`

## 4. 全量城市级数据迁移（可选进阶）

平台自带的 `data_package/` 聚焦于核心示范区（约 7 MB），确保了轻量化与极速开箱即用。若需要在新设备上加载全市域全部 15.5 万座建筑、22 万条道路以及 46 万条社交媒体历史事件，可通过以下方式全量转储：

### 4.1 在源设备上导出全量数据库
利用 PostgreSQL 原生 `pg_dump` 导出压缩归档：
```powershell
# 导出为自包含格式
pg_dump -U postgres -d gis_thermal_shanghai -Fc -f gis_thermal_shanghai_full.dump
```

### 4.2 在新设备上恢复全量数据库
```powershell
# 在新设备创建数据库并开启 postgis
psql -U postgres -c "CREATE DATABASE gis_thermal_shanghai;"
psql -U postgres -d gis_thermal_shanghai -c "CREATE EXTENSION postgis;"

# 恢复全量数据
pg_restore -U postgres -d gis_thermal_shanghai -v gis_thermal_shanghai_full.dump
```

## 5. 常见问题排查 (FAQ)

### Q1: 启动时报错 `Port 8000 is already in use` 或 `Port 5178 is already in use`
- `start.ps1` 内置了端口自愈机制，会在默认端口被占用时自动递增分配可用端口。
- 也可以手动显式指定端口启动：
  ```powershell
  .\start.ps1 -BackendPort 8001 -FrontendPort 5179
  ```

### Q2: 报错 `function st_contains(...) does not exist` 或空间查询失败
- 数据库尚未开启 PostGIS 插件。
- 解决方式：以管理员连接该数据库执行：
  ```sql
  CREATE EXTENSION postgis;
  ```

### Q3: 启动后前端底图显示空白或提示跨域
- 检查 `frontend/.env` 中的 `VITE_TIANDITU_KEY` 是否有效。天地图 Key 每日有免费配额；若无网络或无 Key，系统会自动平滑退化为离线本地 DEM 晕渲底图与建筑白模。
