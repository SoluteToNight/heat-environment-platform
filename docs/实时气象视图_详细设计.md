# 和风实时气象视图：详细设计

版本：v0.1；日期：2026-09-16；状态：设计确定，和风认证数据尚未实际接入。

本设计细化原始设计中的“客观热环境视图必须实时”。相关文档及拟定数据结构在本平台目录独立维护，不同步项目数据字典。

## 1. 用户要求与本期范围

- 采用和风天气提供客观环境气象数据。
- 在上海选定展示范围按约1 km布设预报查询点，逐点获取未来48小时预报并缓存，用插值形成连续可探索视图。
- 温度、湿度、风、露点等变量通过同一次逐小时预报请求取得，不逐变量请求。
- 本期不考虑太阳辐射，不购买辐照服务，也不计算UTCI。优先把多要素气象地图接入三维场景。
- 当前使用者两人，用户表示约10天后展示；本次以短期展示的可运行性、正确标注和调用成本为重点。这里的10天是需求背景，不是已锁定的交付日历。
- 两人共享缓存，地图切换、模型旋转和UGC打卡不会自动触发天气调用。

场景名称可以沿用产品“热环境”方向，但图层具体名称必须准确，例如“气温”“相对湿度”“风速/风向”“露点”。当前估计不称为现场实测，供应商体感温度不称为UTCI。

## 2. 查询点的含义与布设

一个查询位置是一组经纬度，一次请求是向一个接口发起一次成功数据获取。一个位置可以在不同时间请求多次；一次请求也可以包含该位置48小时的多项变量。

布设步骤：

1. 明确展示区域边界，保留米制EPSG:32651与交换EPSG:4326版本。
2. 在米制坐标下建立1000 m间距的规则查询点，不能简单把经纬度各增加0.01°当作严格1 km。
3. 按插值需要配置周边支持点，并将边缘支持点计入预算。禁止用无数据区向外无限插值。
4. 请求前展示或记录总点数、预计调用量与范围。具体数量由边界决定，不固定为先前举例的1、5或10个点。
5. 核验接口坐标约定及返回位置，如相邻查询对应同一有效格点，记录重复关系，避免误认为获得多个独立气象观测。

当前不预设以一个点代表整个上海，也不将约1 km查询间距等同于原生模式分辨率或1 km实测精度。

## 3. 和风接口与字段

使用官方新逐小时接口路径：`/weather/v1/hourly/{latitude}/{longitude}?hours=48`，Host由账号配置提供，认证使用账号支持的JWT或API Key。实际权限、48小时返回长度、单位及缺测需接入时检查。默认接口返回24小时，因此必须显式设置hours=48。

服务端保管凭据，不放进前端代码、文档或Git。返回的JSON包含metadata与hours数组；每条小时记录以forecastTime定位，不能只靠数组下标判断时刻。

| 信息 | 官方新版字段 | 本期用途 |
| --- | --- | --- |
| 预报时刻 | forecastTime | 时间轴、时刻对齐 |
| 气温 | temperature.value/unit | 主着色图层 |
| 相对湿度 | humidity | 湿度图层；接口0—1，展示百分比 |
| 风 | wind.speed.value/unit、wind.direction.degree | 风速着色与风矢量；确认角度和高度约定 |
| 露点 | dewPoint.value/unit | 露点图层与一致性检查 |
| 供应商体感温度 | feelsLike.value/unit | 可选辅助图层，明确非UTCI |
| 阵风、风力等级 | windGust、wind.scale | 地点详情，不混同平均风速 |
| 天气现象 | condition | 地点详情，类别不做数值平滑 |
| 降水 | precipitation | 量、强度、概率和类型；保留累计时间语义 |
| 气压、能见度 | pressure、visibility | 辅助详情；按返回单位解析 |
| 云量、紫外线指数 | cloudCover、uvIndex | 辅助详情；云量0—1，不将UV当作辐射通量 |

这些是文档定义的字段，不保证每条记录必定非空。一个位置的一次48小时调用包含这些变量，不按48个时刻或变量数分别计费。当前天气接口独立，可选增加；它不会自动包含在本次小时预报请求里。

## 4. 获取、缓存与时间

默认每60分钟刷新配置点集的一整批48小时预报，首次进入或服务启动时按需获取。刷新周期可配置，参考产品修订和展示时间调整。持有48小时序列不代表48小时内无需获取新版预报。

服务端以供应方、接口版本、点位、预报长度和时间选项识别请求，保存获取时间、提供方元数据标记、有效时刻序列、原始单位及数据版本。提供方未返回明确起报时间时标为未知，不能用下载时间冒充起报时间。

相同请求共享缓存并合并并发；两位用户同时打开同一区域不会分别拉取整批。切换气象变量、选择已缓存小时、旋转场景或查看已有点位详情不新增供应商请求。跨日、时区及失效缓存需统一处理。

服务端时间统一UTC，前端按Asia/Shanghai展示。时间轴覆盖返回数据有效范围，当前时刻若有可用预报支持则显示“预报驱动估计”；未来选择显示“预报”。

第一版优先显示明确的小时有效值。如果需要平滑到当前分钟，仅在前后两个有效小时之间对适用连续变量做时间插值，并注明估计；无前后支撑不外推。天气类别和降水累计值不套用温度的时间插值规则。10分钟刷新页面不会产生原生10分钟预报。

## 5. 空间插值及一致性

第一版可优先采用规则点阵内双线性插值展示温度等连续变量；需要四个角点有效。若点集不规则，另选并记录适用插值方法及参数，不静默切换或外推。本期不将建筑、树冠或绿地系数叠加成未经验证的气温修正。

- 温度：保持返回单位，插值前统一；保留原查询点用于核对。
- 风：按供应商确认的气象风向约定，先转东西/南北分量，再空间或时间插值，最后还原风速风向；静风时方向不强行赋值。不能直接平均359°和1°。
- 湿度和露点：保留供应商原值，检查范围和露点与气温的关系。若独立插值出现物理不一致，应标记并采用明确记录的热力一致方案，例如从插值后的温度和水汽变量推导其一；派生值不得伪装成接口原值。
- 缺测：不填0；局部支持不全则该变量显示无数据，不能用新旧不明时刻拼接。
- 类别：天气、降水类型和风力等级不直接连续插值。

地图可以比1 km网格显示更平滑，但细像素只是绘制尺度，不能声称获得50 m实际气象信息或树下真实温度。热环境颜色、风矢量和点击数值必须使用相同时间、插值方法和发布版本。

## 6. 场景交互

默认气温着色，提供湿度、风和露点切换；可选体感温度与其他要素详情。风场动画运动速度是视觉编码，应结合图例，不能当作真实三维街谷流场。

时间轴支持“现在”与未来48小时内的有效时刻，未来播放不称为实况。点击位置展示变量值、单位、有效时刻、来源和估计尺度；可展开查看临近查询点原值。

天气图层与建筑、树冠、道路、水体、绿地和UGC叠加。当前阴影可跟随选定场景时刻，但阴影变化不自动改写气温、湿度等字段。UGC按体验时间独立筛选，不把过去打卡当作预报时刻的体验。

## 7. 预算与短期展示

请求预算按实际点数计算，不按使用人数计算。预报单接口每轮每点一次，假设25个点：

| 调度方式 | 10天调用量 |
| --- | ---: |
| 每天8轮（约每小时一轮） | 25×8×10＝2,000次 |
| 每天24轮 | 25×24×10＝6,000次 |

25仅为预算示例，边缘支持点、首次额外获取、补采和其他接口需计入。按已查官方定价，天气和基础服务组每自然月前50,000次免费；额度是组内共享，非每接口独立。后台应限并发、合并重复请求、限制重试并监控月度用量，避免高频地图事件触发调用。

不调用太阳辐照接口，本期不产生其按次费用。缺少辐射不影响温湿风等展示，但不能据此计算或宣称UTCI。成本详情见[调用成本评估](和风天气调用成本评估_20260916.md)。按要求展示和风来源及链接，缓存与公开使用遵循产品许可。

## 8. 异常与验收

- 401/403等认证失败停止该任务并提示配置问题，不持续自动轰炸接口；限流及暂时故障有限退避重试。
- 新批次未完整可用前继续展示旧批次及其真实时间；达到配置过期阈值后明确提示过期。过期阈值在上线配置中记录，不能以48小时预报长度作为固定保鲜期。
- 局部失败保留缺测掩膜，不伪造全区覆盖；新版本发布时统一切换图层和查询。
- 验证每点时序、字段范围、单位、时区和缺失；不因HTTP 200就认定完整有效。
- 验证两位用户共享数据、变量切换和时间轴操作不会额外请求和风。
- 验证输入点原值、空间插值、风向跨0°/360°、静风及边缘缺测处理。
- 验证前端当前/预报模式、更新时间、来源署名、无数据状态和实际接口调用计数。

## 9. 当前状态与待实施项

已完成官方字段和价格文档核对、方案设计；尚未使用账号获取和风业务数据，未建立缓存服务、插值模块或前端图层。展示样区边界及最终点位数量未确定，不能预先按少量点位声称全上海1 km覆盖。

本文件落实用户需求，不触发账号创建、付费开通或业务API请求。实施从实际样区布点、预算确认及凭据配置开始。
