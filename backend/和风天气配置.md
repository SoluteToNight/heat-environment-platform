# 和风天气 JWT 接入

本次实现后端逐小时预报接入，使用官方当前 `GET /weather/v1/hourly/{latitude}/{longitude}`，默认请求 48 小时。不是旧版 `/v7/weather/24h`，也没有用小时预报代替历史观测。当前前后端的通用接口适配仍有历史差异，本次通过后端检查命令验证供应商接入，不将其等同于三维页面已完成联调。

## 1. 准备依赖和密钥

在 `heat-environment-platform/backend` 目录打开 PowerShell，使用项目虚拟环境：

```powershell
& ../../.venv/Scripts/python.exe -m pip install -r requirements.txt
& ../../.venv/Scripts/python.exe -m app.qweather_setup generate-key
```

生成 `secrets/qweather-public.pem` 和 `secrets/qweather-private.pem`。已有同名文件时拒绝覆盖，避免控制台公钥与本地私钥失配。`secrets/` 和后端 `.env` 已加入 Git 忽略；私钥不在日志、API 返回或前端中输出。

打开 **公钥** 文件，将全部内容上传至「和风控制台 → 项目管理 → 项目 → 添加凭据 → JSON Web Token」。私钥留在本机。记录开发者 ID、项目 ID、凭据 ID，以及「控制台 → 设置」中的独立 API Host。

## 2. 填写后端配置

将本目录 `.env.example` 复制为 `.env`，已有 `.env` 时直接编辑并保留数据库等原配置。填入：

```dotenv
WEATHER_PROVIDER=qweather
QWEATHER_API_HOST=你的专属域名.qweatherapi.com
QWEATHER_DEVELOPER_ID=你的开发者ID
QWEATHER_PROJECT_ID=你的项目ID
QWEATHER_KEY_ID=你的凭据ID
QWEATHER_PRIVATE_KEY_PATH=secrets/qweather-private.pem
QWEATHER_JWT_TTL_SECONDS=900
QWEATHER_FORECAST_HOURS=48
```

- Host 只填控制台提供的完整域名，不带 `https://` 或路径。
- 开发者 ID 是以 Q 开头的 10 位字母/数字，对应 `iss`；项目 ID 对应 `sub`；凭据 ID 对应 `kid`。
- 私钥路径支持绝对路径；相对路径固定相对于 `backend/`，不受启动工作目录影响。
- `.env` 固定从 `backend/.env` 加载，系统环境变量优先。修改配置后重启后端。
- 有效期允许 120–86400 秒，默认 900 秒；`iat` 回退 30 秒，令牌到期前 60 秒自动重新签名，无需手工生成或复制 JWT。
- 预报范围允许 1–240 小时，实际权限、额度和费用以账号开通情况为准。
- 未配置 `WEATHER_PROVIDER` 时保留原 Open-Meteo 默认。切换为 `qweather` 后，默认视图和状态只选该供应商；旧发布记录保留。

## 3. 检查与启动

```powershell
# 一次真实 API 请求；不连接数据库、不打印 JWT 或私钥
& ../../.venv/Scripts/python.exe -m app.qweather_setup check

# 平台表已初始化后，手动强制拉取并发布到数据库
& ../../.venv/Scripts/python.exe -m app.qweather_setup sync
```

`check` 成功会显示预报小时数与 UTC 时间范围。随后双击平台目录 `start.bat` 启动前后端。启动时检查所选供应商的发布记录，超过 50 分钟则请求新发布；创建默认环境视图时也会按这个间隔检查。没有独立的后台定时采集任务。

如只验证配置与认证，执行 `check` 即可；`sync` 会产生真实请求和数据库写入，不能在尚未完成控制台配置时宣称验证通过。

## 4. 数据与失败处理

- 请求位置沿用配置中的上海中心，按接口要求取两位小数，默认实际请求 `31.23,121.47`；保存实际请求坐标，不把原始更多小数当作真实精度。当前仅是一个请求位置，不是全市逐像元天气图层。
- 气温 `temperature.value` 保留 °C；`humidity × 100` 转为百分数；风速只接受明确的 m/s；风向 degree 保留度。缺测保存 null，零值保留零。
- API 未明确声明接收高度，因此沿用现有数据库列名 `_2m`、`_10m` 只表示兼容存储；产品目录与来源元数据不宣称已经核实高度。
- 未提供的短波、直射、散射、DNI 保持 null；目录和视图标为不支持。露点等额外字段保留在原始响应元数据中，尚未映射成平台独立查询变量；不计算假 UTCI。
- 发布元数据保存官方原始 JSON、规范化 JSON 的 SHA-256、请求路径、坐标、单位及署名。视图来源返回署名、时间语义和空间支持说明。正文中的天气预报时间不属于 2024 年联合研究观测。
- 401 仅刷新 JWT 后再试一次；403 提示权限；429 传递 Retry-After、不立即重试；网络、格式、单位错误不产生新发布，更不会退回模拟天气。存在旧和风发布时可保留旧版本；新配置尚无发布时环境视图返回 503，其他服务仍可启动。
- `at` 时刻超出和风发布范围时拒绝创建视图，避免把未来预报当历史。`now` 沿用已有最近时刻查询，来源标记为 `hourly_forecast`，不代表实时观测。

## 5. 验证范围

独立单元测试位于 `unit_tests/test_qweather.py`，使用临时 Ed25519 密钥、HTTP mock 和数据库 mock，不访问真实天气服务或修改研究数据库：

```powershell
& ../../.venv/Scripts/python.exe -m pytest unit_tests/test_qweather.py -q
```

真实账号请求需要用户提供控制台配置并执行 `check`；这一步未配置前不视为完成。
